# Спецификация объекта (`spec.json`)

Генератор `scripts/generate.py` читает один JSON. Полный рабочий пример — `examples/coffee-roastery.json`.

## Поля верхнего уровня

| Поле | Обязательно | Что это |
|---|---|---|
| `seed` | нет (1) | Зерно случайности. Тот же `seed` — тот же пакет; другой — другие числа при той же структуре |
| `object` | да | Объект: см. ниже |
| `supply` | да | Энергоснабжение: поставщик, договор, тариф |
| `product` | да | Продукция и суточный выпуск |
| `circuits` | нет | Производственные участки (контуры энергомодели) |
| `equipment` | да | Оборудование |
| `anomalies` | нет | Заложенные потери, которые должен найти анализ |
| `period` | нет | `end` (ISO-дата, конец последнего полного месяца; по умолчанию — прошлый месяц), `bill_months` (12), `telemetry_days` (31) |
| `climate` | нет | `t_mean` — среднегодовая температура, `t_amp` — полуразмах «зима–лето», `t_day_amp` — полуразмах «день–ночь», °C |
| `other_load_kw` | нет | Неучтённая база (дежурный свет, IT), кВт; по умолчанию 3 % суммарной мощности |
| `links` | нет | Связи энергомодели, которые технолог проговаривает в разговоре: что за чем идёт и от чего зависит. Без поля — по участкам, см. ниже |
| `call_notes` | нет | Дополнительные реплики технолога для расшифровки разговора — сюда идёт то, что надиктовал пользователь |
| `resources` | нет | Покупные ресурсы кроме электроэнергии: газ, тепло, вода, жидкое топливо. Без поля — пакет только по электроэнергии, см. ниже |

### `object`

`name`, `company`, `address`, `area_m2`, `timezone` (IANA, например `Europe/Samara`), `assortment` — обязательны.
`climate_zone` (по СП 131.13330, например «II В»), `description` — по желанию.

`shifts`: `title` (как в документах: «2 смены, 08:00–24:00, пн–пт»), `start_hour`, `end_hour` (смена может
переходить через полночь: `22` → `6`), `weekdays` (0 = понедельник; по умолчанию пн–пт).

Климат по городу (ориентиры): Москва `t_mean` 6 / `t_amp` 14; Самара 5,5 / 16; Екатеринбург 3,5 / 17;
Новосибирск 1,5 / 19; Краснодар 12,5 / 12; Санкт-Петербург 6 / 12,5.

### `supply`

`supplier`, `contract_number`, `max_power_kw`, `tariff_rub_per_kwh` (без НДС, текущий) — обязательны.
`tariff_category` (1–6), `supply_points` (список названий вводов; в счетах используется первый).

Ориентир тарифа для малого и среднего бизнеса в 2026 году: 7–10 ₽/кВт·ч без НДС.
`max_power_kw` — примерно 1,3–1,6 × суммы мощностей оборудования, умноженной на коэффициент одновременности 0,6.

### `product`

`title`, `unit` — только `кг`, `т` или `шт`, `daily_min` / `daily_max` — выпуск в рабочие сутки.

### `circuits`

`[{key, title, driver_unit, description?}]`. `key` — латиницей (`roasting`, `machining`). Оборудование
ссылается на контур полем `circuit`.

### `equipment`

| Поле | Что это |
|---|---|
| `key` | Уникальный ключ латиницей |
| `name` | Наименование для ведомости — **см. правила названий ниже** |
| `model` | Марка, модель |
| `count` | Количество однотипных единиц |
| `rated_kw` | Номинальная мощность ОДНОЙ единицы, кВт |
| `profile` | Как работает, см. таблицу профилей |
| `load` | Средняя загрузка в работе, доля номинала (0–1) |
| `idle` | Загрузка вне работы, доля номинала (обычно 0) |
| `location` | Место установки |
| `circuit` | Ключ контура, если оборудование производит продукцию |
| `metered` | Есть ли свой прибор учёта (по умолчанию да) — попадает в `telemetry/` |
| `in_inventory` | `false` — оборудование НЕ попадёт в ведомость, о нём скажет только технолог в разговоре |

Профили:

| `profile` | Поведение |
|---|---|
| `process` | Работает в смену, загрузка растёт с выпуском дня; в нерабочие дни стоит |
| `shift_system` | Обслуживает смену (компрессоры, вакуум, гидравлика): в смену почти постоянно |
| `constant` | Круглосуточно (серверная, холодильные камеры, азот на хранение) |
| `cooling` | Холод: зависит от улицы, днём больше, ночью — дежурный режим |
| `heating` | Электрообогрев: зависит от мороза, ночью 70 % дневного |
| `ventilation` | В смену на `load`, вне смены — `idle` |
| `lighting` | В смену полностью, вне — дежурное |

### `anomalies`

| `type` | Параметры | Что видно в данных |
|---|---|---|
| `off_shift` | `share` — доля номинала вне смены | Нагрузка ночью и в выходные (утечки, не выключили) |
| `no_night_setback` | — | Вентиляция или иная система работает ночью как днём |
| `unit_overconsumption` | `unit` (№ единицы), `extra` (0,41 = +41 %) | Одна из однотипных единиц потребляет больше остальных |
| `drift` | `unit`, `extra` | Потребление единицы растёт последние 8 недель |

У каждой можно задать `title` (как назвать находку в ответах) и `hint` (реплика технолога; `{name}`, `{unit}`).
Две–три аномалии — оптимально: заметно, но не карикатурно.

Аномалии покупных ресурсов вместо `equipment` указывают `resource` (ресурс должен быть в `resources`):

| `type` | `resource` | Параметры | Что видно в данных |
|---|---|---|---|
| `water_leak` | `water` | `lph` — л/ч (по умолчанию 100), `days` — последние N суток (21) | Ночной расход на водомере ввода не падает. Детектор ночной утечки Полиметрики поднимает инцидент с рублями, если у воды есть `meter`, а утечка больше 10 % среднего дневного расхода и 20 л/ч |
| `heating_no_setback` | `gas` или `heat` | — | Отопление ночью и в выходные как в смену. Видно на часовом графике ввода и в счетах; детекторы режима работы Полиметрики смотрят только на электроэнергию, инцидента не будет |

### `resources`

Газ, тепло и вода считаются из тех же часов, выпуска и температуры улицы, что и электроэнергия. Электрическая
часть пакета от них не меняется. Каждый описанный ресурс даёт 12 счетов (у топлива — УПД) в своей папке
`upload/`, а с полем `meter` — строку узла учёта в ведомости и почасовые показания счётчика на вводе.

| Ресурс | Обязательные поля | Расход | Прочее |
|---|---|---|---|
| `gas` | `supplier`, `contract_number`, `tariff_rub_per_1000m3` | `process_m3_per_unit` — м³ на единицу выпуска (горелки, печи); `heating_peak_m3_h` — котельная, м³/ч в сильный мороз. Нужно хотя бы одно | `meter`, `meter_location` |
| `heat` | `supplier`, `contract_number`, `tariff_rub_per_gcal`, `heating_peak_gcal_h` | Отопление от сети, Гкал/ч в сильный мороз | `meter`, `meter_location` |
| `water` | `supplier`, `contract_number`, `tariff_rub_per_m3`, `wastewater_tariff_rub_per_m3` | `process_m3_per_unit` — на единицу выпуска; `domestic_m3_per_work_day` — бытовые нужды за рабочие сутки; `wastewater_share` — доля водоотведения (0,95) | `meter`, `meter_location` |
| `liquid_fuel` | `supplier`, `price_rub_per_l`, `l_per_work_day` | Литры за рабочие сутки (погрузчики, генератор) | `fuel_kind`: `diesel` или `fuel_oil`; `use` — на что идёт |

- `meter` — марка прибора на вводе («Ирвис-РС4», «ВКТ-7», «ВСХНд-40»). Без него счета есть, показаний нет.
- Отопление (газ и тепло) идёт только в отопительный сезон: в сутки со средней температурой ниже +10 °C, ночью
  и в выходные — 60 % дневного. Летом счёт за отопление нулевой.
- Тарифы — без НДС, текущие; до 1 июля счета идут по тарифу на 9 % ниже (индексация). Ориентиры 2026 года:
  газ 7 500–9 500 ₽/тыс. м³, тепло 2 000–3 000 ₽/Гкал, вода 40–60 ₽/м³, водоотведение 35–50 ₽/м³,
  дизель 55–65 ₽/л.
- Своя котельная на газе (`heating_peak_m3_h`) и тепло от сети (`heat`) вместе не задаются: у объекта одно.
- Поставщики — вымышленные, как и электроснабжающая организация.

### `links`

Связи энергомодели: что от чего зависит. Технолог проговаривает каждую в расшифровке разговора, а агент
Полиметрики при разборе собирает их в карточку «Оборудование и учёт» с цитатой из разговора.

| Поле | Что это |
|---|---|
| `from` | Ключ оборудования или `output` — выпуск продукции (агент заведёт узел «Выпуск продукции») |
| `to` | Ключ оборудования |
| `kind` | `metric` — потребление `to` зависит от `from`; `process` — продукт идёт с `from` на `to`; `unmeasured` — `to` работает вместе с `from`, своего прибора нет |
| `method` | Только у `metric`: `regression` — пропорционально выпуску (от `output`); `window` — работает, пока работает `from`, вне этого окна — потери; `window_const` — то же, но нагрузка ровная |
| `say` | Своя реплика технолога вместо шаблонной. Название `to` в ней — как в ведомости, иначе агент не узнает узел |

Без поля `links` связи строятся по участкам (`circuits`, по порядку): первый измеряемый `process` участка —
от выпуска (`regression`), продукт идёт с участка на следующий (`process`), остальное оборудование
участка — в окне его процесса (`window`), неизмеряемое — `unmeasured`. Оборудование вне участков
(компрессоры, ККБ, свет) связей не получает: их агент предложит сам по показаниям приборов. Если
технолог должен сказать, что компрессоры работают на фасовку, задайте это явно полем `links`.

## Правила названий оборудования

Помощник Полиметрики сопоставляет строку ведомости с классом каталога по самому длинному совпавшему
названию или синониму. Класс даёт узлу модели номинальную мощность и методы расчёта. Поэтому:

1. Если оборудование подходит под класс каталога — используйте его название или синоним в `name`.
2. Не упоминайте в названии другой класс: «Вытяжка ростеров» станет ростером, пишите «Вытяжка участка обжарки».
3. Отраслевое оборудование вне каталога (печь, пресс, мешалка, экструдер…) пишите как есть — помощник
   добавит его в модель как процесс **без номинальной мощности** (классы проекта появятся в платформе позже).
   Предупредите об этом пользователя.

Классы каталога:

| Класс | Название | Синонимы |
|---|---|---|
| `roaster` | Ростер | ростер, обжарочный аппарат, жаровня |
| `packing_line` | Линия фасовки | фасовка, упаковка, фасовочная линия |
| `compressor` | Компрессор | компрессор, сжатый воздух |
| `compressor.screw` | Компрессор винтовой | винтовой компрессор |
| `nitrogen_generator` | Азотная станция | азотная станция, генератор азота, азот |
| `ventilation.supply` | Приточная установка | пв, приток, приточная вентиляция |
| `exhaust` | Вытяжка | вытяжка, аспирация |
| `chiller` | Чиллер | чиллер, холодильная машина |
| `chiller.condensing_unit` | Компрессорно-конденсаторный блок | ккб |
| `air_conditioner.ducted` | Канальный кондиционер | канальный кондиционер, кондиционер |
| `cooling_tower` | Градирня | градирня |
| `cnc_machine` | Станок с ЧПУ | чпу, станок, фрезерный станок, токарный станок |
| `injection_molding_machine` | Термопластавтомат | тпа, термопластавтомат, литьевая машина |
| `dryer.granules` | Сушилка гранул | сушилка, сушилка гранул |
| `mold_thermostat` | Термостат пресс-формы | термостат, термостат формы |
| `heating` | Отопление цеха | отопление, обогрев |
| `lighting` | Освещение | освещение, свет |

Общие для любой отрасли: компрессоры, вентиляция, вытяжка, холод, кондиционеры, отопление, освещение.
Почти любой цех можно собрать из 3–5 общих систем и 1–3 отраслевых процессов.

| `upload/02_Договор_энергоснабжения.docx` | Договор | Поставщик, номер договора, макс. мощность, ценовая категория, вводы, тариф |

| `upload/счета/Счёт_ГГГГ-ММ.pdf` × 12 | Счёт за электроэнергию | Ряды: кВт·ч, сумма, тариф по месяцам |
| `upload/05_Отчёт_о_выпуске_по_месяцам.xlsx` | Отчёт о выпуске | Выпуск по месяцам (кроме последнего) |

| `upload/счета_тепло/Счёт_тепло_ГГГГ-ММ.pdf` × 12 | Счёт за тепло | Ряды тепла: Гкал, сумма, тариф ₽/Гкал |

| `upload/топливо/УПД_топливо_ГГГГ-ММ.pdf` × 12 | Накладная на топливо | Ряды топлива: литры, сумма, цена |
| `telemetry/показания_приборов_учёта_<газ\|тепло\|вода>.csv` | Показания приборов учёта | Почасовые показания счётчика на вводе нарастающим итогом; прибор привязывается к узлу ввода своего ресурса из ведомости |
| `ЧТО ЗАЛОЖЕНО.md` | — | Ответы: потери в кВт·ч и ₽ в год, связи, которые должен собрать агент; объёмы, рубли и CO₂ по ресурсам, потери по ресурсам |
| `summary.json` | — | Сводка для Claude |

Документы составлены под правила распознавания Полиметрики: ключевые слова в заголовках, подписи колонок
(«Наименование», «Кол-во, шт», «Мощность, кВт», «Месяц», «Выпуск продукции, кг», «Расчётный период»,
«Объём, кВт·ч»). Не переименовывайте колонки и заголовки вручную.
